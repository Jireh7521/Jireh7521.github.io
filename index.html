01 / Selected work

Things I have shipped, not just started.

Six projects that show how I work: a game that installs like an app, a helpdesk with real auth, a mapped directory, and an AI tool built with the key kept on the server.

JavaScript·solo build

Lighthouse Hunter

A five-zone side-scrolling adventure, written without a framework: canvas rendering, hand-painted backdrops, checkpoint saves and a global leaderboard.

  • A 41-test harness plus CI that fails the build on any drift between source and published files.
  • Installable PWA: a hashed service worker precaches all 33 assets so it opens and plays offline.
  • One control scheme for keyboard, touch and gamepad, with a mandatory tutorial before the timer starts.

Python·team of two

CampusFlow

A support helpdesk for campus staff: priority rules, assignment, follow-up notes and reports, running as both a CLI and a local web app on the standard library.

  • I owned authentication and persistence: salted PBKDF2-HMAC-SHA256 at 600,000 iterations.
  • Web sessions rotate on sign-in and sign-out, expire after 30 idle minutes, with CSRF tokens and a same-origin CSP.
  • Ticket writes are serialized so two requests can never overwrite each other's changes.

Emergency Resource Map

A map-first directory of hospitals, fire services, shelters and IDP camps, with category filters and a "find near me" search built on the browser's geolocation.

  • FastAPI and PostgreSQL behind Alembic migrations, with admin-only create, edit, delete and verify routes.
  • React front end handling search, clustering and nearby lookup without a page reload.
  • One docker compose up brings up Postgres, the API and an nginx-served front end.

Python·AI tool

Cyber Threat Detection AI

Paste firewall, IDS or auth logs and get a streamed analyst first pass: a written threat report, indicators of compromise mapped to MITRE ATT&CK, and a plain-English read.

  • The model key lives only on the FastAPI server; the browser never sees it.
  • Logs are wrapped as untrusted data so an injection buried in traffic cannot rewrite the instructions.
  • The summary arrives as its own stream event, so risk and confidence cards show real values, not regex guesses.

02 / About

Junior by title, careful by habit.

I started with HTML, CSS and JavaScript, building small browser tools, and kept going into Python and then Go. Today I work across both ends: a canvas game with a service worker on one side, a FastAPI service with migrations and auth on the other.

What I enjoy most is the part after the first version works: finding the race condition, tightening the password hashing, adding the test that would have caught it. In CampusFlow that meant rotating sessions, CSRF protection and serializing ticket writes. In Lighthouse Hunter it meant a build check that refuses to publish when source and output disagree.

I use AI tools as a learning partner, not an oracle. I read what they give me, run it, and test behaviour before it reaches a project, and I have built with LLM APIs myself, including a log analyser that treats incoming text as hostile.

I am looking for a junior or internship role where code review is normal and security is not an afterthought. I would rather be told my design is wrong early than ship it twice.

04 / Working with AI

Fast with tools, accountable for the code.

"If I cannot explain a line, it does not go in." How I review anything a model hands me
  1. 1
    Read it line by line.I trace the data and check the types and edge cases myself.
  2. 2
    Run it locally.It has to work in my environment, not just in the chat window.
  3. 3
    Test the behaviour.I add or run tests before accepting the change.
  4. 4
    Assume input is hostile.Especially model input: logs, prompts and user text get treated as data.
